## Mobile-friendliness audit — LexFlow site (frontend-developer-lovable_react)

- Ole reported: on his phone the site shows no menu — expected a hamburger/sandwich dropdown. Audited the live homepage `https://lexflow-site.pages.dev/lexflow-index` (hash-verified identical to local `lexflow-index.html` `5ab27835…` and `assets/style.css` `8da550d5…`).
- **Confirmed root cause (CRITICAL):** `assets/style.css:351-352` `@media(max-width:860px){ .nav-links{display:none} }` hides the 6 main links on any screen ≤860px, and **no hamburger element exists anywhere** (0 matches for hamburger/burger/sandwich in HTML, 0 menu-toggle logic in any of the 6 JS assets). So on a phone the primary nav is unreachable — the footer only links Privacy/Terms/Cookie, not the main pages.
- **Other mobile defects found:**
  - **HIGH — hero stays 2-column on mobile.** The hero `.wrap` carries an inline `style="display:grid;grid-template-columns:1.1fr .9fr;gap:48px"` (inline styles beat the stylesheet, no `!important` override exists). At 390px the two columns collapse to ~161px/133px → headline and CTAs wrap into many lines, image squished. Present in 5 EN pages + it/ru copies (index, how-it-works, practice-areas, pricing).
  - **MEDIUM — "Sign in" hidden on small phones.** `assets/style.css:364` `@media(max-width:480px){ .nav-cta .btn-ghost{display:none} }` removes the primary auth action ≤480px.
  - **LOW — pricing `compare-table`** (font 12px at ≤860) can overflow horizontally on narrow phones (tables don't wrap).
- **Proposed fix (awaiting Ole's go — nothing changed yet):** add a hamburger toggle + mobile dropdown in `assets/style.css` and a button in each page's `<nav>` (source templates `templates/lexflow-*.html`, then regenerate EN/it/ru via `templates/build-lang-sites.py` and `dist/` via `templates/build-dist.py`); collapse the hero grid to 1 column at ≤860 via an `!important` media rule; restore Sign in inside the mobile menu. Local preview first, no deploy.
