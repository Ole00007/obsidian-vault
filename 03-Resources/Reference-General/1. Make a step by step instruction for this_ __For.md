Hermes’ docs also support the install order you quoted: get the CLI working first, then run `hermes gateway setup`, then attach messaging/platform connectors and only after that scale into multi-profile operation.[^1][^2][^3][^4][^5][^6]

## Gateway setup

Use this sequence for bot or always-on use, because Hermes docs recommend configuring the base agent first and only then starting the messaging gateway.[^3][^5][^1]

1. Install Hermes Desktop/CLI and finish the initial provider setup with Nous Portal so models and Tool Gateway tools are available.[^4][^3]
2. Start the CLI and verify basic chat works before touching gateways.[^3]
3. Create the first profile: `operator-installer`, and keep it as the only active profile during initial setup.[^6]
4. Run `hermes gateway setup` and choose one platform first, ideally Telegram because the docs give the clearest guided setup and it supports straightforward bot testing.[^5][^7]
5. Start the gateway in the foreground, test inbound and outbound messages, then check status.[^7][^5]
6. Only after the first gateway works, add more platforms one by one; Hermes supports Telegram, WhatsApp, Email and other messaging platforms through the gateway subsystem.[^8][^9][^1]
7. For platforms not covered by the built-in gateway flow, connect them via MCP where possible, because Hermes explicitly treats MCP as the path to external services and tools beyond the core gateway adapters.[^10][^2][^4]
8. For multiple agents on messaging platforms, do not reuse the same token across multiple profiles unless you intentionally want them sharing one identity, because Hermes warns that shared tokens can conflict across profiles.[^11][^12]

## Platform mapping

Your requested platform list needs one clarification: not all of those services belong to the same setup category. The clean breakdown is:[^1][^4][^8]

- **Messaging gateway platforms:** Telegram, WhatsApp, WhatsApp Business Cloud API, Email, and similar chat surfaces.[^13][^14][^9][^1]
- **Google Workspace/OAuth tools:** Gmail, Google Drive, Calendar, Docs, Sheets; Hermes has a dedicated Google Workspace skill for these.[^15][^16]
- **MCP/integration services:** GitHub, Notion, Google Drive access patterns, databases, file systems, browser automation, and many other third-party systems.[^2][^10][^4]
- **Likely custom or MCP/plugin route rather than native documented gateway:** Instagram, Meta Business, Google Business, Netlify, Railway, OpenRouter, Cloudflare, Canva, CapCut, Edits, Perplexity.[^17][^4]

That means you should **not** try to wire everything through `hermes gateway setup` literally. The better architecture is: gateway for chat channels, Google Workspace skill for Google services, MCP for operational tools, and plugins/custom adapters where no first-party flow exists yet.[^15][^17]

## Specialization rules

To make the team truly specialized, each agent should have:

- Its own profile boundary, because Hermes profiles own config, memory, sessions, cron, logs, gateway state, and related agent data.[^6]
- Its own soul file, so behavior stays consistent across sessions.[^10]
- Its own memory file with strict persistence rules, especially because Hermes recommends consolidating memory before it becomes overloaded.[^19]
- Its own skills folder or skill set, because Hermes’ skills system is intended to make reusable workflows available cleanly instead of bloating the base prompt.[^20][^18]
- A limited MCP tool subset, because Hermes recommends filtering MCP tools rather than exposing everything everywhere.[^21][^22][^2]

The confusing part in your current setup is the overlap between **memory-curator** and **librarian**. A good split is:

- **memory-curator** = agent-internal memory, prompts, skills, profile hygiene.
- **librarian** = external knowledge systems, folders, docs, drives, SOP archives, retrieval structure.

That keeps one focused on Hermes’ internal cognition layer and the other on your business knowledge estate.

## Operator sharpened

- New MCP servers are installed one at a time, tested, filtered, then assigned to the minimum viable set of agents.[^22][^21]
- The operator maintains the master routing table: which tasks go to which agents, which MCPs they may use, and which messaging channels map to which profile.[^12][^6]
- The operator also observes self-improvement outputs and decides whether a learned pattern becomes a memory, a skill, or a prompt revision.[^18][^20]

That should be inserted into the first two operator prompts, the master plan, and the profile/soul/memory docs.
