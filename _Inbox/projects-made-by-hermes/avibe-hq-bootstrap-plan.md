# avibe-hq Remediation & New-Laptop Bootstrap Plan (updated after live check)

> Generated by memory-curator — audit of the self-hosted Hindsight memory bank `avibe-hq` and the LexFlow 23-profile fleet. Updated 2026-08-28 after the live bank query.

## Live check results (2026-08-28)
- Bank is **HEALTHY**: `GET /health` → `{"status":"healthy","database":"connected"}`; `GET /version` → `{"api_version":"0.9.1", "features":{...}}`.
- Bank `avibe-hq` currently holds **8,895 memory units** (`/v1/default/banks/avibe-hq/memories/list` → `total:8895`).
- Contents are predominantly from `operator-installer`'s 2026-08-27 AGENT_RULES-rollout session (fact_type observation/experience, tagged `session:20260827_134425_cd32d1`, `metadata.agent_identity: operator-installer`). So `operator-installer` was **already retaining to avibe-hq successfully** — the bank was never empty.
- Auth uses the key provided by the user (`8f3b…e0f`); it is valid (all endpoints answered).

## What was actually wrong (fragmentation)
| Issue | Impact |
|---|---|
| Only `operator-installer` had a working Hindsight setup (real key + bank `avibe-hq`). The other 22 profiles used `provider: ''` (local memory) or had no hindsight config. | Their session memories stayed local — not in avibe-hq. |
| Profiles with `provider: hindsight` but **no profile-local `hindsight/config.json`** silently fell back to the default bank name `hermes` (wrong bank). | Any non-operator hindsight profile would have written to a separate, empty `hermes` bank. |
| `default` profile `memory.provider` was `''` (its `config.json` existed but was orphaned). | Even the default wasn't feeding avibe-hq. |
| `.env` `HINDSIGHT_API_KEY` was `***` (placeholder) in most profiles. | Those profiles couldn't auth via `.env` — but `config.json` `apiKey` now overrides this (see fix). |

## What was changed (Step 2 — applied)
- Created `hindsight/config.json` (`bank_id: avibe-hq`, `api_url: https://avibe-hindsight-production.up.railway.app`, `mode: local_external`) in **all 23 profiles + default**.
- Set `memory.provider: hindsight` for the 20 `''` profiles + default (`operator-installer` already correct).
- **Distributed the real API key via `config.json` `apiKey`** (NOT `.env` — `.env` is write-protected, and the plugin reads `apiKey` from `config.json`, which takes precedence over the broken `.env` `***`). This also fixes the `operator-installer` regression my earlier bulk `>>` may have caused.
- Left `memory-curator` on `supermemory` (its curation backend) — flagged. `tester` is a stray empty dir.

## New-laptop bootstrap (what a fresh device still needs beyond avibe-hq)
`avibe-hq` is **memory-only**. A fresh laptop cannot bootstrap LexFlow from it alone. It also needs:
1. Hermes + the 23 profile definitions (`config.yaml` now → avibe-hq, `skills/`, `cron/`, session DBs, and each profile's `.env` with real API keys).
2. The full Obsidian vault (avibe-hq only holds re-ingested `vault/Hermes/*.md` notes).
3. The real `HINDSIGHT_API_KEY` (now encoded in each profile's `hindsight/config.json`).
4. Runbook: clone profiles + vault, set real keys in `.env`, restart Hermes, verify one profile retains + recalls.
